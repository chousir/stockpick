## 0. TL;DR 與定位：市場層第三塊拼圖

repo 現有**兩個**市場層模組，本次是**第三個**，三者職責互斥、週報 Section 0 並列：

| 模組 | 視角 | 資料 | 回答的問題 |
|---|---|---|---|
| `data/macro.py` 事件行事曆（既有） | 前瞻**事件** | 手動 YAML | 未來 30 天有什麼雷（FOMC/CPI/結算） |
| `analysis/regime.py` V2 大盤 regime（既有） | 內生**市場內部結構** | 台股價量＋法人 | 台股自己現在的姿態（趨勢/廣度/資金 → 進攻/中性/防禦） |
| **`analysis/macro_regime.py`（本次新增）** | 外生**總經狀態** | FRED＋TWSE | 全球宏觀環境現在的系統性風險水位（綠/黃/紅） |

劃界鐵則：**不合成**。總經燈號與 V2 regime 各自輸出、並列揭露，不做加權合一——
兩者資料源、時間尺度、失效模式都不同，合成會把「誰在說話」洗掉。讀法（寫進 docs/11）：
外生紅＋內生防禦＝強共振警訊；外生紅＋內生進攻＝背離（歷史上常是頭部左側），值得人工細看。

**v2 新增劃界**：不合成這條鐵則，v1 只用在「燈號 vs V2 regime」這個外層。實測（round 3）發現
**燈號內部也不該合成**——把多個總經指標加權平均、再取合成分數，測出來會稀釋訊號而非放大
（等權/CI比例兩種權重方案都全格輸給單一最強指標）。所以 v2 的核心設計改成
**單一主訊號決定燈色＋其餘指標並列揭露、不進計分**，跟外層的「不合成」精神一致，只是往下推了一層。

核心設計主張（各節展開，v2 更新）：
1. **單一資料源優先**：FRED 一站覆蓋利率/信用/波動/油價/雙匯率，**零新依賴**（httpx＋Polars 即可）；不用 yfinance（依賴 pandas，鐵律 4 禁用）。已用官方 API key 驗證可行（`.env`）。
2. **單一主訊號，不加權合成**（v2 改）：`BAA10Y`（Moody's Baa 公司債對 10 年公債利差）經三輪回測驗證為單一最穩健指標（headline lift 2.26〔CI 1.61–3.06〕，round1+round2 全部 8 格通過），由它單獨決定燈色；其餘指標降級為輔助揭露欄位，不進計分公式。
3. **水位×變速雙分量**（沿用）：委託動機是「殖利率**快速**上升」——只看水位百分位抓不到急變，只看變速會漏高原期，兩者都要。主訊號用水位分量（level_pct，實測中最穩健的轉換）。
4. **防假訊號**（v2 簡化）：單一訊號不需要「群組共振」這道閘（v1 為了防單指標誤觸而設計的多群組共振機制，在只有一個計分訊號的 v2 設計下不適用）；改用**遲滯帶**（沿用）＋**揭露面板交叉檢視**（新增讀法：主訊號紅但揭露面板全部平靜＝可能是單一指標雜訊，值得人工多看一眼，跟外層「共振/背離」讀法同一個精神，往內層再套一次）。
5. **誠實標註**：v1 全部指標權重都是未校準先驗；v2 的候選/排除清單改為**有實測依據**（三輪 block-bootstrap lift/CI），但主訊號與揭露面板之間仍未做「整體 as-of 回放」驗證（見 §6 Phase 2），色階門檻的黃/綠切點也還是先驗，故 v2 報表仍標〔實測篩選,門檻未校準〕，不是完全轉正。

### 依賴拍板（已定案）

**零新依賴，FRED 走官方 API。** 使用者已註冊免費 key（存於 `.env`，不進 git）：

- 匯率/VIX/信用利差都在 FRED：`DEXTAUS`（注意：v1 草案誤植為 `DEXTAIUS`，正確代碼已用 curl 驗證修正）、`VIXCLS`、`BAA10Y`。

抓取合規（鐵律 1 精神外推到新資料源，實作時同步補進 docs/02）：
循序抓（concurrency=1）、序列間隔 ≥1 秒、同序列 24h 快取、連錯 3 次停、逾時明確 raise、UA 可設定。
FRED 是官方開放資料，限制遠鬆於 Goodinfo，但慣例統一省心。

**新風險（研究中發現，v1 沒預料到）**：FRED 官方序列的歷史涵蓋範圍可能被追溯限縮——
`BAMLH0A0HYM2`（v1 原信用利差候選）2026/4 起被限縮到僅剩約 3 年歷史，直接導致該序列在 3 年滾動窗
設計下完全無法計分。這不是端點失效，是資料源本身的授權變動，且無法事先預警。見 §5 風險 10。

## 3. 燈號評分公式設計（v2 全面簡化：單訊號，無合成）

### 3.1 主訊號計分

```
level_pct = BAA10Y 當前值在近 3 年（≈756 觀測）分布中的百分位 ∈ [0,1]，嚴格因果（每個時點只用該時點以前的資料）
risk_score = level_pct × 100  ∈ [0, 100]
```

不再有 v1 的 `w_level × level_pct + w_speed × speed_pct` 合成——三輪研究裡 level_pct 是 BAA10Y 唯一
拿到最強實測數字的轉換（headline ci_lo 1.606，speed_pct 只有 1.085），直接用最強的那個,不強行湊
水位+變速雙分量（水位×變速的設計理念沒有錯,只是 BAA10Y 剛好是水位分量比較強;VIXCLS/DCOILWTICO
剛好是變速分量比較強——這也是為什麼揭露面板保留了不同指標各自的最強轉換,見 §2.2）。

### 3.2 燈色門檻與遲滯帶

```
基準門檻：綠 < 60 ≤ 黃 < 80 ≤ 紅   〔紅燈門檻=80,對應三輪研究實際檢驗過的「前20分位=高風險」定義；
                                      黃綠切點是未校準先驗,標註清楚〕

遲滯帶：換色需突破門檻 ±3 分（黃→紅需 ≥83,紅→黃需 <77）；帶內維持上週顏色，防門檻附近週週閃爍
```

**v2 拿掉了 v1 的「紅燈需 ≥2 群組共振」閘**——那是為了防止單一指標雜訊誤觸紅燈而設計的多群組
機制，在只有一個計分訊號的 v2 設計下沒有對象可以共振。取而代之的讀法（人工介入,非程式門檻）：

> **燈色紅但揭露面板（DGS20/VIXCLS/DCOILWTICO/STLFSI4）也全部偏高＝強共振,可信度高；
> 燈色紅但揭露面板平靜＝可能是 BAA10Y 單一序列的雜訊或個別事件,值得人工多看一眼再判斷。**

這跟 §0 外層「總經燈號 vs V2 regime」的共振/背離讀法是同一個邏輯，只是往內層再套一次——
不是程式擋，是報表把兩層資訊都攤開，人自己讀。

### 3.3 缺資料處理（簡化）

- BAA10Y stale／未取得 → 燈號整體降級「**資料不足**」（灰），不給綠燈。
- 揭露面板任一指標 stale → 該行印「未取得」，不影響燈色（面板是脈絡不是計分項，缺一項不擋主判定）。

## 4. 與週報流程的整合

### 4.1 插入點（三處，全比照 V2 regime 既有形狀，沿用 v1）

1. **`make week`**：在 `rotation` 之後、`group` 之前掛 `-$(MAKE) macro`（容錯前綴：FRED 掛了不擋整條週流程）。
2. **`group_runner.py`**：載入 `data/macro_regime/history.parquet` 最新一列 → 傳 `macro_light` dict 進 `render_group_report`；讀不到／過期 → 傳 None。
3. **`group_report.py` Section 0**：緊鄰「大盤姿態」行渲染「總經燈號」段；None → 整段不渲染。

### 4.2 週報輸出格式（Section 0 新段，v2 改版）

```markdown
### 總經燈號（外生風險）：🟡 黃 68/100（主訊號 BAA10Y，as-of 2026-07-30）〔實測篩選,門檻未校準〕

主訊號：Baa公司債利差 2.14%（p68，20日+8bp）〔2026-07-30・FRED BAA10Y〕　較上次 ↑ +14.0p〔前次 2026-07-23〕

輔助揭露面板（不計分，供交叉參考）：
| 指標 | 現況 | 較上次 | 揭露 |
|---|---|---|---|
| DGS20（20年期殖利率） | 4.71%（p61） | → -0.3p〔前次 2026-07-23〕 | 〔2026-07-30・FRED DGS20〕 |
| VIXCLS（VIX 變速） | 20日 +6.2pt（speed p71） | ↑ +22.1p〔前次 2026-07-23〕 | 〔2026-07-30・FRED VIXCLS〕 |
| DCOILWTICO（油價急動） | 20日 −9.1%（dual_risk p58） | ↓ -2.9p〔前次 2026-07-20〕 | 〔2026-07-30・FRED DCOILWTICO〕 |
| STLFSI4（金融壓力指數） | 0.31（p55） | ↑ +35.8p〔前次 2026-07-17〕 | 〔2026-07-24・FRED STLFSI4，週頻〕 |
| DGS10（10年期殖利率，未通過驗證僅供參考） | 4.82%（p85） | → +0.01〔前次 2026-07-23〕 | 〔2026-07-30・FRED DGS10〕 |

- 讀法（燈色）：主訊號黃，揭露面板普遍溫和偏高但未過半極端——弱共振，維持觀察不升級。
- 讀法（變化・M-Macro4／docs/26）：看「較上次」不要只看水位——水位百分位在單向趨勢序列上會
  常駐高位（實測 DGS20 近兩年 34% 取樣點 ≥p90），p99 本身鑑別力低，同一格急衝才是資訊；
  主訊號綠/黃但面板多格同時急變＝燈色公式看不到的情境，值得人工細看。
- 與上方大盤姿態（內生 V2 regime）並列對照——同紅＝強共振；背離＝人工細看（外層讀法，見 docs/11）。
- 顏色較上週：綠 → 黃（BAA10Y level_pct 54 → 68）。
```

「較上次」＝與**上一輪 `make macro`** 的同序列讀數相比（間距非固定 7 天，前次資料日期附在格內）；
deadband 內顯示「→」、無前次顯示「—」；**純揭露，不進計分、不改燈色、不影響排序或剔除**。

**箭頭語意分兩種，報表已標警語**：`level_pct`／`speed_pct`／`dual_risk` 的 ↑＝風險升高；
`raw` 三列（DGS10／DEXTAUS／DEXJPUS）無風險分數，箭頭只是數值方向——**DEXJPUS ↓（日圓走強）**
才是 carry unwind 的警戒方向（§2.2 留它的理由）、DEXTAUS ↑（台幣走弱）才是外資流出方向。
不把 raw 列的方向硬轉成「風險方向」是刻意的：DEXJPUS 的 dual_risk 框架三輪研究皆無證據
（§2.2、Phase 2 tail-event 重測），程式沒有立場說哪邊是風險，只能把方向攤開讓人讀。
明細落地 `reports/2026-Wxx/macro_regime.csv` 不變；歷史累積在 `data/macro_regime/panel_history.parquet`。

搭配落地：`reports/2026-Wxx/macro_regime.csv`（主訊號＋揭露面板全部指標明細：原值/level_pct 或
speed_pct 或 dual_risk/as-of/來源）供你在週報階段跟 Claude Code 互動深挖。

### 4.3 報告紅線對齊（鐵律 2，沿用 v1）

燈號語言只到「風險水位揭露＋姿態提示」，比照 `regime.py` 的 `_ADVICE` 分寸：
紅＝「系統性風險水位高，評估分批降低曝險/暫緩新進場」；**不出現**任何買賣結論、目標價、
禁用詞。每個數字附觀測日與序列 ID。標題列常駐〔實測篩選,門檻未校準〕標籤。

### 4.4 CLI

`tw-screener market macro`（掛在既有 market app 下，與 `market regime` 並肩）：
印當前燈號（主訊號）＋揭露面板全部指標＋各序列 as-of＋「較上次」變化（M-Macro4）；
`--refresh` 略過快取強抓。

### Phase 4 — V2 regime 單獨作為早期警報的誠實診斷（2026-08-23，docs/31 大重構延伸提問）

**背景**：docs/31 使用者提出「你 make week 時做總經檢視，能否提早發現 2022-2026 較大跌幅」——
這問的不是本文件主線的 BAA10Y 外生燈號（Phase 3 已證實跟 V2 regime 共振讀法在目前資料裡
結構性測不了），而是**V2 regime 本身**（`analysis/regime.py`，進攻/中性/防禦，趨勢/廣度/
資金三分數合成）在使用者實際會用它的方式下——「regime 轉防禦時，是不是已經在跌勢發生前
或發生早期就示警」——是否稱職。這跟 Phase 3 的「共振 lift 值」是不同問題：lift 高不代表
**提早**，一個訊號可以「防禦期報酬確實比較差（lift 顯著）」但同時「轉防禦的時間點本身
已經落後大跌」，兩者不矛盾，必須分開驗證。

**方法**：直接核對 V2 regime 逐日標籤歷史（`regime_history.py`產出，2022-01~2026-07可信窗，
同Phase 3已確認的資料邊界）與2022-2026三個公認較大跌幅事件的實際發生時間點，人工比對
「regime轉防禦」的日期 vs「跌勢／崩盤日」的日期，算領先或落後的交易日數與同期累積跌幅。

**結果（三個事件皆查核，非挑樣本）**：

| 事件 | regime轉防禦（持續） | vs 跌勢 | 判定 |
|---|---|---|---|
| 2022年空頭 | 2022-04-25 | 已下跌約70個交易日、累積-13.6%後才轉 | **落後** |
| 2024-08-05 台股史上最大單日跌幅（碳交易平倉） | 2024-08-09 | 崩盤日後4個交易日、低點後3個交易日才轉 | **落後** |
| 2025-04 美國對等關稅衝擊 | 2025-03-28 | 領先最劇烈的04-07~09約6個交易日，但緩跌段已先走了約25個交易日、-8%才轉 | **部分領先**（只接住後段急跌，漏掉前段緩跌） |

**誠實結論：V2 regime 目前是滯後/同步確認工具，不是可靠的早期警報系統**。三個事件裡兩個
明確落後（且落後幅度不小，2022年那次落後超過3個月的下跌時間與規模），只有一個有部分
領先、且領先的是急跌段而非整個下跌的起點。**不可以把「regime轉防禦」當成使用者要的
「提早警惕」訊號來用或這樣介紹給使用者**——它比較適合的定位是「確認目前處境有多糟」，
不是「預告接下來會變糟」。這跟Phase 3已經記錄的「V2防禦 alone lift=2.40（n=152，相對
穩健）」不衝突：**防禦期報酬確實顯著更差（lift成立），但轉防禦的時間點本身經常太晚**，
兩件事分開才看得清楚，只看lift容易誤以為regime有預警能力。

**本輪範圍與不做的事**（docs/31使用者拍板：先寫進文件，不開新研究）：
- 只做診斷、不修改`analysis/regime.py`計分邏輯或`config/settings.yaml`參數。
- **不開新的領先指標研究**（如信用利差走闊、波動率期限結構倒掛等）——這是規模更大、
  獨立的研究題目，留待使用者未來想做時再另行提出、另開milestone，本輪不代為決定範圍
  也不搶跑。
- 三個事件的比對是人工讀取regime歷史+已知公開跌幅事件日期，非新的自動化回測框架/
  純函式，未來若要把這個問題做成正式的、可重跑的驗證（如系統性掃描更多歷史跌幅事件、
  算lead time的CI），需要另外設計，本節只是把這輪已經做過的人工核對誠實記錄下來。
