## 0. TL;DR 與定位：市場層第三塊拼圖

repo 現有**兩個**市場層模組，本次是**第三個**，三者職責互斥、週報 Section 0 並列：

| 模組 | 視角 | 資料 | 回答的問題 |
|---|---|---|---|
| `data/macro.py` 事件行事曆（既有） | 前瞻**事件** | 手動 YAML | 未來 30 天有什麼雷（FOMC/CPI/結算） |
| `analysis/regime.py` V2 大盤 regime（既有） | 內生**市場內部結構** | 台股價量＋法人 | 台股自己現在的姿態（趨勢/廣度/資金 → 進攻/中性/防禦） |
| **`analysis/macro_regime.py`（本次新增）** | 外生**總經狀態** | FRED＋TWSE | 全球宏觀環境現在的系統性風險水位（綠/黃/紅） |

劃界鐵則：**不合成**。總經燈號與 V2 regime 各自輸出、並列揭露，不做加權合一——
兩者資料源、時間尺度、失效模式都不同，合成會把「誰在說話」洗掉。讀法（寫進 docs/11）：
外生紅＋內生防禦＝強共振警訊；外生紅＋內生進攻＝背離（歷史上常是頭部左側），值得人工細看。

**v2 新增劃界**：不合成這條鐵則，v1 只用在「燈號 vs V2 regime」這個外層。實測（round 3）發現
**燈號內部也不該合成**——把多個總經指標加權平均、再取合成分數，測出來會稀釋訊號而非放大
（等權/CI比例兩種權重方案都全格輸給單一最強指標）。所以 v2 的核心設計改成
**單一主訊號決定燈色＋其餘指標並列揭露、不進計分**，跟外層的「不合成」精神一致，只是往下推了一層。

核心設計主張（各節展開，v2 更新）：
1. **單一資料源優先**：FRED 一站覆蓋利率/信用/波動/油價/雙匯率，**零新依賴**（httpx＋Polars 即可）；不用 yfinance（依賴 pandas，鐵律 4 禁用）。已用官方 API key 驗證可行（`.env`）。
2. **單一主訊號，不加權合成**（v2 改）：`BAA10Y`（Moody's Baa 公司債對 10 年公債利差）經三輪回測驗證為單一最穩健指標（headline lift 2.26〔CI 1.61–3.06〕，round1+round2 全部 8 格通過），由它單獨決定燈色；其餘指標降級為輔助揭露欄位，不進計分公式。
3. **水位×變速雙分量**（沿用）：委託動機是「殖利率**快速**上升」——只看水位百分位抓不到急變，只看變速會漏高原期，兩者都要。主訊號用水位分量（level_pct，實測中最穩健的轉換）。
4. **防假訊號**（v2 簡化）：單一訊號不需要「群組共振」這道閘（v1 為了防單指標誤觸而設計的多群組共振機制，在只有一個計分訊號的 v2 設計下不適用）；改用**遲滯帶**（沿用）＋**揭露面板交叉檢視**（新增讀法：主訊號紅但揭露面板全部平靜＝可能是單一指標雜訊，值得人工多看一眼，跟外層「共振/背離」讀法同一個精神，往內層再套一次）。
5. **誠實標註**：v1 全部指標權重都是未校準先驗；v2 的候選/排除清單改為**有實測依據**（三輪 block-bootstrap lift/CI），但主訊號與揭露面板之間仍未做「整體 as-of 回放」驗證（見 §6 Phase 2），色階門檻的黃/綠切點也還是先驗，故 v2 報表仍標〔實測篩選,門檻未校準〕，不是完全轉正。

抓取合規（鐵律 1 精神外推到新資料源，實作時同步補進 docs/02）：
循序抓（concurrency=1）、序列間隔 ≥1 秒、同序列 24h 快取、連錯 3 次停、逾時明確 raise、UA 可設定。
FRED 是官方開放資料，限制遠鬆於 Goodinfo，但慣例統一省心。

**新風險（研究中發現，v1 沒預料到）**：FRED 官方序列的歷史涵蓋範圍可能被追溯限縮——
`BAMLH0A0HYM2`（v1 原信用利差候選）2026/4 起被限縮到僅剩約 3 年歷史，直接導致該序列在 3 年滾動窗
設計下完全無法計分。這不是端點失效，是資料源本身的授權變動，且無法事先預警。見 §5 風險 10。

## 3. 燈號評分公式設計（v2 全面簡化：單訊號，無合成）

### 3.1 主訊號計分

```
level_pct = BAA10Y 當前值在近 3 年（≈756 觀測）分布中的百分位 ∈ [0,1]，嚴格因果（每個時點只用該時點以前的資料）
risk_score = level_pct × 100  ∈ [0, 100]
```

不再有 v1 的 `w_level × level_pct + w_speed × speed_pct` 合成——三輪研究裡 level_pct 是 BAA10Y 唯一
拿到最強實測數字的轉換（headline ci_lo 1.606，speed_pct 只有 1.085），直接用最強的那個,不強行湊
水位+變速雙分量（水位×變速的設計理念沒有錯,只是 BAA10Y 剛好是水位分量比較強;VIXCLS/DCOILWTICO
剛好是變速分量比較強——這也是為什麼揭露面板保留了不同指標各自的最強轉換,見 §2.2）。

### 3.2 燈色門檻與遲滯帶

```
基準門檻：綠 < 60 ≤ 黃 < 80 ≤ 紅   〔紅燈門檻=80,對應三輪研究實際檢驗過的「前20分位=高風險」定義；
                                      黃綠切點是未校準先驗,標註清楚〕

遲滯帶：換色需突破門檻 ±3 分（黃→紅需 ≥83,紅→黃需 <77）；帶內維持上週顏色，防門檻附近週週閃爍
```

**v2 拿掉了 v1 的「紅燈需 ≥2 群組共振」閘**——那是為了防止單一指標雜訊誤觸紅燈而設計的多群組
機制，在只有一個計分訊號的 v2 設計下沒有對象可以共振。取而代之的讀法（人工介入,非程式門檻）：

> **燈色紅但揭露面板（DGS20/VIXCLS/DCOILWTICO/STLFSI4）也全部偏高＝強共振,可信度高；
> 燈色紅但揭露面板平靜＝可能是 BAA10Y 單一序列的雜訊或個別事件,值得人工多看一眼再判斷。**

這跟 §0 外層「總經燈號 vs V2 regime」的共振/背離讀法是同一個邏輯，只是往內層再套一次——
不是程式擋，是報表把兩層資訊都攤開，人自己讀。

### 3.3 缺資料處理（簡化）

- BAA10Y stale／未取得 → 燈號整體降級「**資料不足**」（灰），不給綠燈。
- 揭露面板任一指標 stale → 該行印「未取得」，不影響燈色（面板是脈絡不是計分項，缺一項不擋主判定）。

## 4. 與週報流程的整合

### 4.1 插入點（三處，全比照 V2 regime 既有形狀，沿用 v1）

1. **`make week`**：在 `rotation` 之後、`group` 之前掛 `-$(MAKE) macro`（容錯前綴：FRED 掛了不擋整條週流程）。
2. **`group_runner.py`**：載入 `data/macro_regime/history.parquet` 最新一列 → 傳 `macro_light` dict 進 `render_group_report`；讀不到／過期 → 傳 None。
3. **`group_report.py` Section 0**：緊鄰「大盤姿態」行渲染「總經燈號」段；None → 整段不渲染。

### 4.2 週報輸出格式（Section 0 新段，v2 改版）

```markdown

主訊號：Baa公司債利差 2.14%（p68，20日+8bp）〔2026-07-30・FRED BAA10Y〕

輔助揭露面板（不計分，供交叉參考）：
| 指標 | 現況 | 揭露 |
|---|---|---|
| DGS20（20年期殖利率） | 4.71%（p61） | 〔2026-07-30・FRED DGS20〕 |
| VIXCLS（VIX 變速） | 20日 +6.2pt（speed p71） | 〔2026-07-30・FRED VIXCLS〕 |
```
