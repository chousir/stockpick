## 2. `make week GROUP=defg` 覆蓋範圍（使用者提問的直接回答）

**M1–M6 的所有機器產物都在 `make week` 一條指令內**，不需要任何額外指令：

| 模組 | 產物 | 由 week 的哪一步產出 |
|---|---|---|
| M1 | `contrarian_ready` 欄 | ⑨ group → `candidates_enriched.csv` |
| M2 | 投降洗盤偵測段 | ⑨ group → `group_analysis.md` regime 段 ＋ 歷史 parquet |
| M4 | 三個轉折早段欄 | ⑨ group → `candidates_enriched.csv` |
| M4 | 轉折埋伏清單 | ⑨ group → `inflection_ambush.md`＋2 個 csv |
| M5 | `deep_value_growth` 欄 | ⑨ group → `candidates_enriched.csv` |
| M6 | 上週帳＋分桶回饋帳 | ⑫ pick-outcome-brief → `pick_outcome_brief.md` |
| M3 | 停損延遲帳（全期） | ❗ **不在 week 內**：季度 `make pick-outcome`（設計如此，week 內只有 M6 的週頻摘要） |
| M8 | 三態判定與披露 | ⑪ week-check 讀 `macro_risk_latest.yaml` 並印狀態 |

**兩個 by-design 的例外，必須講清楚——「make week 就能實現所有事情」不完全成立**：

1. **`macro_risk_latest.yaml` 是人工貼進去的**（裁決 D）。`make week` 只**消費與
   驗證**它，不產生它。來源是獨立的每日掃描 project（docs/28）。缺席完全合法。
2. **週報本身仍是人工貼檔流程**。`make week` 產出的是**輸入包**；docs/11 的
   ProPicks prompt 要你貼給 Claude Opus 才生出週報。M3/M5/M7 的 prompt 側規則
   （條件單停損語意、高PE 新規、六個 patch）自然要等那一步才會作用。

換句話說：**機器該做的事，`make week GROUP=defg` 全包了**；剩下兩件事一件是貼一個
yaml（30 秒、可略），一件是貼輸入包生週報（本來就是這套系統的設計）。

## 3. 差異清單（實作 ≠ 委託書原文之處，全部照原式實作＋加但書，無一自行收緊）

### ① M1 的前提事實與委託書不符（最重要一條）

委託書裁決 A 寫「**回測完成前即解禁**」。事實是：**回測已完成，且結果為負**——
docs/24 §3.1 記錄「兩條件桶（基本面完好＋外資轉買，無位階條件）已**否證**」。

處置：**照裁決 A 執行**（使用者有權做人工裁決，且已在委託書明寫「人工裁決、非統計
證據」），但把每一份產物的措辭鎖成「**兩條件桶已否證；三條件桶未測、且先驗不利**」，
不准寫成「未驗證」——後者會讓讀者以為只是還沒做。docs/24 新增 §6 記錄解禁本身，
含「什麼被否證了／什麼從沒測過」對照表。M1.6 回收條款是這個解禁的必要對價。

### ② M4.2 產物位置：`cp_candidates.md` → `inflection_ambush.md`

委託書寫「產出到 cp_candidates.md 新段」。但 `make week` 的順序是
⑧ cp-value-candidates → ⑨ group，`cp_candidates.md` 在 `candidates_enriched` 的欄位
存在**之前**就寫完了，而轉折埋伏的四個條件全部依賴那些欄。硬塞回去只能靠事後改寫
別的步驟的產物（髒）。改為獨立產物，並同步進 docs/11 貼檔清單與 week-check。

### ③ `base_zone=貼底` 的語意陷阱（M4.2／M5 都碰到）

委託書多處以 `base_zone=貼底` 表示「價格在底部」。但本 repo 的 `base_zone=貼底`
＝**距季線 MA60 ≤ +10%**（docs/20 §WS5-①），量的是「未延伸／回到季線 base」，
**不是「貼近 60 日低點」**。2026-W32 實跑中 7610 距季線 +4.2%（＝貼底）但距 60 日低
**+133.6%**。

- **M4.2**：原式是「貼底 **或** 距低 ≤10%」，OR 讓兩種不同的低位階混在一表。
  照原式實作，但加 `位階依據` 欄攤開「距低型／僅貼底型」、距低型排前、開頭警語
  明寫兩者論述不可混用；M7 patch-3 同步要求分析師照這欄讀。
  要收掉貼底分支是一行 settings：`inflection.ambush_allow_base_zone_branch: false`。
- **M5**：原式是「距季線 <0 **或** 貼底」——兩條都是 MA60 口徑，**無混用問題**，直接照做。

### ④ M7 patch-1 的「距 low_60d ≤8%」與程式的 ≤5% 不一致

委託書 patch-1 文字寫 ≤8%，但 `contrarian_base` 實作用的是
`base_proximity ∈ {在低,貼低}`＝**≤5%**。**沒有改門檻、也沒有在 prompt 裡造第二套
定義**：patch-1 改為「一律以 `contrarian_ready` 欄為準，條件文字是語意說明」，並明寫
程式較嚴、不得自行放寬到 8%。要不要真的放寬到 8% 是門檻決策，留給使用者走 settings diff。

### ⑤ M9 部署說明的 yaml schema：`of` 不是常數 7

委託書 M8 的 schema 範例寫 `of: 7`。但本 repo 依 docs/26 §6.2(5) 把 `of` 解讀為
「**已求值項數**」而非常數 7（7 條硬觸發常有 1–2 條抓不到）。docs/28 的掃描 prompt
附加段因此明寫「`of` 誠實寫小，coverage 警語才會正確出現」——寫死 7 會讓下游以為
分母很厚，把「0–2 觸發」誤讀成「風險已清」，那正是 docs/26 §2 要防的事。

## 4. 過程中發現、且與委託書判斷相反的證據（照實記錄）

### ① M3 的停損延遲成本在本樣本中是**正的**（延遲反而有利）

委託書的診斷是「週頻覆核＝追認最大回撤」。M3 的延遲帳實跑（全期底帳，
**n=35 可量測**、中位 +1.37%、最差 AES-KY −12.76%）出來的平均延遲成本是
**+3.07%**——也就是這批樣本裡，**晚一點停損比照條件單停損好**。

（同一次實跑另有 **75 筆 `unparsed`**——停損欄抽不出絕對價，比可量測的還多一倍，
見下方 ②。這也意味著 +3.07% 這個數字建立在一個**有選擇性的子樣本**上。）

這不推翻改制（樣本小、且兩種延遲要分開看：結構性的「一個週期」延遲 vs 行為性的
「續抱數週」延遲，後者才是真正要防的），但**不能拿「延遲有害」當已證事實**。
數字照登在報表 §6。

### ② 2026-W28 的停損欄 17 筆中 **0 筆可量測**

全因停損寫成「跌破季線停損」這類抽不出絕對價的敘述——這正是 patch-2 要修的行為。
M6 的「上週帳」第三格因此印「未取得（17 筆中 0 筆可量測）」，把原因一起印出來，
否則沒人會去改。

### ③ 價格快取密度缺陷會污染等權大盤基準（**未修，已知風險**）

`load_market_history` 的每日成員數在 2026-07 那段是 647 → 1873 → 6409 → 5005 →
1422 → 6015…，日與日之間差一個數量級。等權指數把這些日子串起來會算出假的巨幅
漲跌（W28 brief 印出「大盤 −16.3%」、17 檔 picks 有 16 檔「跑贏大盤」，就是這個）。

- M2 內部**已修**（`dense_days()` 密度守門＋insufficient_data 退化＋振幅但書），
  但**只在 washout 模組內**——刻意不動 `regime`／`rotation`，避免本輪把「加一條腿」
  變成「重寫基準口徑」。
- 因此 **M6 的 α／「跑贏大盤」／`n_beat_market` 三欄承接同一風險**，讀的時候
  **只看桶間相對比較（gap 欄），不要當絕對 α 讀**。
- 根治要嘛補齊日線快取（`make backfill-universe-history`），要嘛把密度守門推廣到
  `compute_market_index`。**兩者都超出本委託書範圍，列為下一輪候選**。
