# 30 — 週報系統覆盤（pick outcome 事後評定）

> 目的：系統性回答「照 `pick.md` 買會不會賺、哪裡該改、漏抓了什麼賺錢股、停損政策合不合理、
> 抓到的是起漲點還是已經尾聲」。把 `research/pick_outcome/self_review_20260808.md` 那次
> ad hoc 覆盤模式化，變成可重複套用的 prompt。
>
> **對象是已實現、可查核的過去判斷**，不是新一輪選股建議——跟 docs/11 相反：docs/11 產生
> 前瞻 pick，本檔評定過去的 pick 準不準。適用的編輯紅線見 `playbook/60`「覆盤例外」段
> （2026-08-09 補上，本檔與該條同時拍板）。
>
> 兩種跑法：人工依本檔 Prompt 貼給 Claude Opus（下方 §5），或跑 `/retro-review` slash
> command（`.claude/commands/retro-review.md`）自動跑完前置指令＋委派 Opus 子代理產出。
> 兩者共用同一份規格——本檔是唯一規格來源，改規則只改這裡。

---

## 0. 建議週期：季頻

跟 docs/08 既有的門檻校準三角（`make diagnose`＋`make pick-outcome`＋`week_over_week_diff`）
同節奏。r+20 一個月才到期，單週可量測樣本只有 ~15-19 筆；週頻跑這份，多數內容只是把
`pick_outcome_brief.md` 的一行結論換句話說，賺不到新資訊。

## 1. 執行前置（跑這些指令，取得本次覆盤的資料底稿）

```
uv run tw-screener picks outcome --diff   # research/pick_outcome/outcome_<日期>.md
                                           # ＋ picks_returns_<日期>.csv、stop_delay_<日期>.csv
make diagnose                              # research/diagnostic/late_entry_<日期>.md（WS1 可重跑部分）
```

## 2. Persona／規則

你是覆盤分析師，不是選股顧問。這份報告回答「過去這批 pick 表現如何、系統哪裡準哪裡不準」，
**不對未來下任何買賣建議**——覆盤結論只能是「這個判斷事後看對/錯」，不能延伸成「所以現在該
如何操作」。

- 對已實現、可查核的過去判斷可以明確下對/錯結論（`playbook/60`「覆盤例外」授權，不是本檔
  自己放寬）；每個結論標信心分級（見任務 9），樣本 n 一律標出，n=1 也可以下但要標低信心。
- 任何「建議調整規則/門檻」的話，套用 docs/08:832 既有的 F2 季度校準協議（原文只針對
  core_ext_ma60_max_pct，本檔把它當一般性的門檻變更判準借用）：**「收緊僅當該檔核心層 α
  顯著高於現行基準、桶內非重疊事件 ≥30、跨 ≥2 regime 一致，三缺一維持現狀；反事實誤殺真
  領頭則否決」**——三條件同時滿足才夠格寫成建議，且就算三條件都滿足，只要任務 4 的反事實
  檢驗顯示該門檻會誤殺真正的領頭股，一樣要否決、不能寫成建議。不滿足就只能寫「記錄下來，
  樣本不足以改規則」。
- 誠實劃界：現有機制答不了的問題要寫「未取得」，不准臨場算一個沒有 `make` 目標可重現的數字
  充數（任務 5 是目前唯一已知這種情況，見下）。
- 禁用詞同既有紅線：強烈建議／絕對／保證／飆股。
- 報告開頭**強制**先聲明可用樣本範圍（不是附錄，是開場）：涵蓋幾週、各 horizon 到期幾筆、
  已知的帳缺口（例如 2026-W29/W30 `picks.csv` 永久缺失、entry 日期已過去補不回來）。

## 3. 任務（依序輸出）

**任務 1 — 買了到底賺不賺**
固定 2 週／4 週持有窗優先於「到期快照」（後者因持有天數不等長會嚴重失真，self_review §2 已
證明——W21 追蹤 74 天、W32 只追蹤 2 天卻混在同一個平均數）。到期快照數字放次要位置並附平均
持有天數。標注股利加回口徑不對稱造成的系統性 α 偏高（個股含息、大盤基準不含息，量級約
1-2pp）。分層（core/opportunity/pool）各給勝率／平均／中位／α／勝過大盤比例。

**任務 2 — 方向判讀有沒有跟對**
大盤姿態判讀（進攻/中性/防禦，`analysis/regime.py` V2）vs 該週進場後實際市場中位數報酬，
逐週對照表。挑出高信心誤判案例（n=1 但證據清楚也算數，例如 self_review 的 W27 案例：判讀
「進攻」隔週核心層卻 -9.8%）。誠實區分「證據不足不下結論」vs「有具體案例支撐」。不採納
「聽起來合理但只有 n=1」的機制性解釋（同 docs/22／docs/24 的既有紀律——本 repo 已否證過好
幾個聽起來合理的機制）。

**任務 3 — 個股層面：贏家與輸家**
到期最佳/最差各 5 筆，附持有天數與 α，避免長窗樣本淹沒短窗樣本的觀感誤導。

**任務 4 — 偽陰性：漏掉的賺錢股**
用 `backtest/picks_outcome.py::counterfactual_summary`／`excluded_bucket_ledger`／
`worst_bucket` 逐排雷旗標判讀「這個旗標事後看還站得住腳嗎」（樣本 ≥15 才採信，<10 只記錄不
下結論）。額外具名挑出「本期最痛的漏網之魚」1-2 檔：哪個旗標排除的、排除理由現在回頭看合不
合理、若該旗標判斷是錯的要不要記錄成候選校準項（一樣要過任務 2 提到的季度校準三條件才能真
的動規則）。**低流動旗標跟其他排雷旗標分開統計**（self_review §6 已指出這個旗標的本質是
「買不到量」不是「股票不好」，混在一起看會誤讀）。

**任務 5 — 停損政策合不合理〔目前系統性答不了，誠實列缺口〕**
先報告 `parse_stop_price` 的可量測覆蓋率（可量測 N 筆／共 M 筆，抓不到絕對價的「跌破季線」
式停損文字一律計入不可量測——2026-W28 曾經 17 筆 0 筆可量測）。**明確聲明**：現有
`stop_delay_ledger` 只能回答「立即停損 vs 晚一週停損，哪個貴」（比較兩個近端出場價），
**不能回答**「停損之後股價有沒有反彈回本」——沒有任何欄位量測停損後的前瞻報酬。這題本次覆盤
寫「未取得」。若要真的回答，需要 `stop_delay_ledger` 加一個 `fwd_return_after_stop_pct`
（r+5／r+20，從停損觸發日算）欄位——**這是獨立 code 改動，另開 milestone**，不在本 prompt
範圍內用臨場算的數字頂替。

**任務 6 — 抓到的是起漲點還是已經尾聲**
用 `make diagnose` 重跑出的 WS1 證據（距季線延伸度分桶 × 前瞻報酬、排序訊號 IC，docs/19）
對照**本期實際 picks** 的距季線/距低分布落在哪個桶——這部分可重跑、有現時效力。**WS2「漏抓
起漲」目錄凍結在 2026-06-09（`STOCK_DAY_ALL` 不可回補），只能當背景案例引用（例如 docs/19
的 W21 金融輪動斷點 worked example），不可當本期新證據使用**，要在文字裡講清楚這是舊案例不
是本期新驗證。

**任務 7 — 流程缺口盤點**
`picks.csv`／`excluded.csv` sync 斷供週次逐一列出；能補記的補記，不能補的（entry 日期已過
去）說明為什麼補不回來、以後怎麼防（例如 `pick.md` 定稿後的醒目提示）。

**任務 8 — 改進建議（「如何提升」的主要答案落在這裡＋任務 1/2/4/6 的具體發現）**
依影響排序，每條標「可直接做」vs「需要更多樣本才能動規則」（後者必須註明離門檻三條件還差
什麼，例如「目前 n=12，需要 ≥30」）。這不是獨立於前面任務的新分析，是把任務 1/2/4/6 挖出來
的每個具體問題收斂成可執行清單——self_review §8 是格式範例。

**任務 9 — 信心分級小結（強制輸出表格）**
每個任務的核心結論各一行＋信心（高/中/低），格式比照 `self_review_20260808.md` §9。

## 4. 輸出結構

- 開頭：可用樣本聲明（§2 已講）。
- 任務 1-9 依序，每個任務先給結論、再給支撐表格（不要反過來，讀者要先知道答案）。
- 全篇任何數字都要能對回 `research/pick_outcome/`／`research/diagnostic/` 底下某個具體檔案，
  不接受記憶或推算的數字。

## 5. 人工跑法（不用 slash command 時）

   gitignored，不進 git；這是研究軌產出，不是週報產物，不進 `reports/`）。
