# 14 — 進場階梯 × 組合層修法（M-修法7 規劃書）

> **定位**：承接 pick.md 盲點修法系列（M-修法1–6，見 [docs/08](08-milestones.md)），這一輪修的是
> **進場階梯的權重/層級邏輯**與**組合層的因子集中**——不是個股判讀（那塊修法 1–6 已大幅補強），
> 而是「**怎麼把選出來的股分批承接、停損擺哪、整盤別全押同一個事件**」。
>
> 來源＝使用者貼入的外部分析 Part A，經 Opus 4.8 對 `reports/2026-W25/pick.md` 與
> `docs/11` 逐條查證（2026-06-21）。**Part B 研究軌（買方主導度單調性／個股×族群交互／payoff·decay
> 四件套）已決定另開一份規劃書與分支，不在本輪**（見 §5）。
>
> 沿用 `CLAUDE.md`「Milestone 紀律」——**一次只做一個 milestone，做完跑驗收、停下等使用者說
> 「下一個」，不要連續執行**。本檔是規劃書；執行時各子項的勾稽清單同步 append 進 docs/08「M-修法7」。

## 0. 一句話目標

把進場階梯從「**最大注押在最深一層、停損坐在進場價上**」改成「**前重後輕、停損與最深批脫鉤**」，
並在組合層加一條「**同因子簇上限**」，讓單一總經事件（如 PCE）不會同時打到大半部位。

**「做完」的定義（success criteria）**：
- W26+ 重跑後，核心股的進場階梯**配比前重後輕**，且**停損價不再等於任一進場批的價**。
- MA20≈MA60 的低價股**自動退化成兩階＋一停損**，不再印「三階 30/40/30」假精度。
- 報告出現一條**因子簇/族群上限**檢核（如利率敏感簇合計部位上限），違反時明標。
- 核心 vs 機會的**籌碼主導標準一致**（投信主導進核心要嘛比照外資標準、要嘛明標例外理由）。
- T3 不再寫「待 Goodinfo 週線確認」——用管線算出的 `low_60d` 直接填。
- 全程**純加法、不動篩選器**（守修法 6 同精神：揭露＋判讀，不加硬性自動踢除）；`make test` 綠。

## 2. 設計決策（待使用者拍板・附推薦）

這幾項是**你的交易紀律**，不是工程預設值，我給推薦但請你在 review 本檔時確認/調整：

**D1・階梯權重 scheme（現 30/40/30）**
- 推薦：**前重後輕**。健康起漲/主升續勢 → **T1 50% / T2 30% / T3 20%**（最大注在最先到、最可能成交的淺批）。
- 理由：最大一筆不該只在「跌到季線、論述可能已破」時才成交。
- 替代：保守者可 40/35/25；或對「剛起漲、想先卡位」者 60/40 兩階。**門檻進 settings 不寫死**（但這是 prompt 約定，實作上是 docs/11 文字＋可調說明）。

**D2・停損與最深批脫鉤（現停損＝T2＝MA60）**
- 推薦：停損改「**收盤確認跌破 MA60**（隔日不收復即出）」，**不**讓任何進場批坐在停損線上；最深批 T3 擺在
  **MA60 之上一點**（前波低 `low_60d`）、留出 MA60 當最後防線的緩衝帶。
- 理由：MA60 同時當「最大加碼點」又當「停損點」邏輯打結。收盤確認破可避免日內假跌破洗掉。
- 替代（較複雜，**預設不做**）：MA60 − k×ATR。需新增 ATR 欄，違反簡單優先；先用「收盤確認」這個不需新資料的版本。

**D3・回檔深度 anchor（現一律 MA20）**
- 推薦：保留 T1≈MA20 為主，但**用 `low_20d`/`high_20d` 做合理性檢核**——若「等回 MA20」距現價 > ~8%
  （如華航 −10%），明標「此 MA20 拉回過深、可能不來；屬強勢股，改走買強勢階梯」而非死等。
- 理由：把 ⑤ 的縫補在「判讀」層，不另立新公式。**這條與 D5 連動**。

**D4・因子簇/族群上限（新增一條組合層規則）**
- 推薦：定義「**利率敏感簇**＝銀行＋建材營造＋產險＋壽險」，規則「**同一簇進核心至多 2 檔、且該簇合計
  ≤ 已部署資金的 ~50%**」；超過時報告明標「因子集中、PCE/利率事件單點風險」並要求降一檔到機會/觀察。
- 理由：⅓ 單檔上限擋不住「3 銀行＋建材＋產險＝5 檔同向」。**簇定義與門檻% 進 settings**。
- 待你定：簇成員清單、上限%（50%？60%？）、是「至多 N 檔核心」還是「合計部位%」或兩者都要。

**D5・核心籌碼主導標準一致性（⑦a）**
- 推薦：核心門檻明文寫成「**外資主導 OR 投信主導皆可，但須同向不對作；若投信主導，明標『投信主導、外資未領頭』
  並列為觀察重點**」——讓聯詠這種投信主導股進核心是「明示的、帶但書的」，不是標準不一。
- 替代：嚴格派＝核心一律要外資主導，投信主導只能進機會。**待你選哪種。**

> 上述 D1–D5 我會在規劃書定稿後依你的選擇寫進 docs/11；**未定者執行時先停下問**，不自己選。

## 3. 分階段 milestone（M-修法7・按序）

> 一次一個、各自跑驗收後停。7a 是 code（其餘 prompt 要用它的欄位），先做。

### 7a — 計算欄位先行（code・純加法，比照修法 6）
- **做什麼**：在主候選管線加 `low_20d` / `high_20d` / `low_60d` / `high_60d`（近 20/60 日收盤滾動 min/max 的**絕對價**）。
- **怎麼做**：在 `momentum`/餵 `members` 的來源層算滾動 min/max → 透過
  [`_build_enriched_rows`](../src/tw_screener/report/group_report.py#L631) 帶出 → 加進 `_CANONICAL_REUSE_FIELDS`
  與 writer（candidates/holdings/watchlist 共用，同修法 6 的 `foreign_net_5d/10d`、`ret_10d` 模式）。
- **不做**：ATR（D2 已決定用「收盤確認破 MA60」，不需 ATR；要時再另議）。
- **驗收**：
  - [ ] candidates_enriched.csv 出現四欄；既有欄與輸出**逐值不變**（純加法）。
  - [ ] holdings/watchlist enriched 同步有四欄（共用 `_build_enriched_rows`）。
  - [ ] 抽查 2–3 檔：`low_60d` ≤ `low_20d` ≤ close ≤ `high_20d` ≤ `high_60d` 合理；對得起日線。
  - [ ] `make test` 綠；ruff/mypy 零淨增。

### 7b — 進場階梯重構（docs/11 prompt・吃 D1/D2/D3 + 7a 欄位）
- **做什麼**：改 [docs/11:192-193](11-propicks-analysis.md#L192) 的階梯規格——
  (i) 配比改 D1；(ii) 停損與最深批脫鉤（D2），T3 用 `low_60d` 填、不再 defer；
  (iii) **MA20 與 MA60 價差 < ~2% → 退化成兩階＋一停損**，不印三階假精度（D3 低價股）；
  (iv) 「等回 MA20」距現價 > 門檻 → 改判強勢股走買強勢階梯（D3/D5 連動）。
- **驗收**：
  - [ ] W25 重跑：核心股配比前重後輕；停損價 ≠ 任一進場批價；遠東銀/王道銀（MA20≈MA60）印兩階非三階。
  - [ ] 華航類（近端外資強買、乖離 <40%、MA20 拉回 >8%）改走買強勢階梯、不死等 MA20。
  - [ ] 所有核心 T3 都有具體 `low_60d` 價、無「待 Goodinfo 確認」字樣。
  - [ ] 守人設：仍多空並陳、不下買賣結論、不給目標價；門檻說明可調。

### 7c — 組合層因子簇上限（docs/11 prompt・吃 D4）
- **做什麼**：在任務 2 的事件閘門段（[docs/11:196](11-propicks-analysis.md#L196) 附近）加一條「因子簇/族群上限」檢核。
- **驗收**：
  - [ ] W25 重跑：3 銀行＋建材＋產險被偵測為利率敏感簇集中、報告明標單點事件風險並要求降檔。
  - [ ] 簇定義與門檻寫在 `config/settings.yaml`，prompt 引用、不寫死數字在敘述裡。

### 7d — 分級一致性（docs/11 prompt・吃 D5）
- **做什麼**：把核心 vs 機會的籌碼主導標準寫成一致規則（D5 選定版）。
- **驗收**：
  - [ ] 聯詠這類投信主導進核心者，報告明標「投信主導、外資未領頭」但書（或依嚴格派降機會）。
  - [ ] 核心入選理由的籌碼標準前後一致、可追溯。
